# NAMESTR padding fixtures

Input fixtures of `VariableXptPaddingTest`. They pin that the XPT reader skips the two padding
fields of a NAMESTR record, `nfill[2]` and `rest[52]`, whatever bytes a writer leaves there
(TS-140: "UNUSED, FOR ALIGNMENT AND FUTURE" and "remaining fields are irrelevant"). Neither file is
part of any shipped artifact.

| fixture | md5 | provenance |
|---|---|---|
| `phuse_send_1_bg.xpt` | `3127fcb1b964a6d09918d1b1c804fc3d` | **third-party, unchanged**: byte copy of `data/send/CBER-POC-Pilot-Study1-Vaccine/bg.xpt` in `github.com/phuse-org/phuse-scripts` (git blob `1cdb2a1b4180ed806348fad3a0a7856f8803ae2a`, compared against commit `398a6d33ced9359ffb58c46650a6d488811176b1`, HEAD of `master`, retrieved 2026-10-15); the local copy is `/data/testdata/phuse-scripts/send_1/xpt/bg.xpt`. SEND body-weight-gain example data of that pilot study, not real study data. Its NAMESTR records carry two ASCII blanks in `nfill`. Licence below. |
| `namestr_blank_rest_3x3.xpt` | `7ea6560fba3e1106a57169ee67b05884` | **generated by this project**: written by `generate-namestr-blank-rest-fixture.py` beside it from the TS-140 record layout, not by this product's writer; synthetic values, no third-party data. Its NAMESTR records carry 52 ASCII blanks in `rest`. Rerunning the script reproduces it byte for byte. |

The authority for the record layout is SAS: TS-140 and SAS 9.4, with this project's own
SAS-9.4-valid exports. ReadStat (pyreadstat 1.3.3 `read_xport`), which reads both files and agrees
with the expected values in the test, is a secondary cross-check only, not the oracle. Accepting
wrong input from other writers is fine, expecting it is not, and writing it is worse (owner,
2026-10-15).
